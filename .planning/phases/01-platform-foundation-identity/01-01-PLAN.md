## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| registry → workspace | Package names, versions, tarballs, and lifecycle scripts enter the repository through a package manager. |
| agent → owner | A tool warning cannot be silently converted into install approval. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | npm registry package metadata | mitigate | Compare registry metadata, npmjs package page, official repository, and official documentation before approval; pin the exact version. |
| T-01-02 | Spoofing | `vitest` name similarity | mitigate | Preserve the SUS verdict and require the blocking owner-decision gate before any install; the gate is never auto-approved. |
| T-01-SC | Tampering | npm installs | mitigate | `slopcheck`/research disposition plus the blocking owner gate; only the exact reviewed version may be installed, and the lockfile is committed later. |
| T-01-04 | Tampering | package-manager supply chain | mitigate | Pin `packageManager` to the verified `pnpm@11.5.2` and provision it through Corepack; a different pnpm major is an owner change and must be escalated, never adopted silently at execution time. |
</threat_model>
