<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated caller → lifecycle endpoint | A user requests an irreversible action that affects identity and business obligations. |
| local database → provider boundary | Local anonymization and external Clerk revocation have different failure semantics. |
| deleted subject → API | An old signed token attempts to re-enter the system after local deletion. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Spoofing | deleted subject replay | mitigate | Durable owner-selected tombstone is checked before provisioning and after deletion in tests. |
| T-08-02 | Elevation of Privilege | cross-user deletion | mitigate | Endpoint derives only the current user; no target ID accepted; cross-user API test returns denial. |
| T-08-03 | Tampering | retained order/store records | mitigate | No user-row deletion or cascade; stable ID and `ON DELETE RESTRICT` preserve records, proven against real PostgreSQL. |
| T-08-04 | Information Disclosure | anonymization/tombstone | mitigate | Clear profile fields, owner-selected keyed/raw form, no raw subject in logs, and explicit retained-field documentation. |
| T-08-05 | Denial of Service | merchant closure | mitigate | Owner-selected state/obligation rule prevents stranded in-flight work; no background timer or guessed legal expiry. |
| T-08-06 | Repudiation | provider failure/local commit | mitigate | Append-only lifecycle event records local/provider outcome without tokens or profile values. |
| T-08-07 | Tampering | admin capability during deletion | mitigate | Admin removal is an explicit local lifecycle operation, never an implicit email-refresh side effect. |
</threat_model>
