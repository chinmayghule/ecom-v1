<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application → PostgreSQL | External input reaches a durable relational system through an ORM and migration SQL. |
| environment → CLI/runtime | URLs and secrets configure two different database connection paths. |
| lifecycle transaction → retained records | Anonymization and capability changes can affect business records and audit history. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | user/store/order foreign keys | mitigate | Use `ON DELETE RESTRICT`, prove constraints in a real database, and make the user row stable/anonymized rather than deleted. |
| T-04-02 | Spoofing | Clerk subject uniqueness | mitigate | Unique database constraint on the external subject plus deterministic conflict handling in Plan 06. |
| T-04-03 | Information Disclosure | database configuration/logs | mitigate | Typed env validation, separate direct/runtime URLs, and sanitized startup failures that never print connection strings. |
| T-04-04 | Tampering | migration history | mitigate | Named reviewed SQL migration, no `db push`/auto-sync, empty-database apply test, and immutable committed migration. |
| T-04-05 | Denial of Service | pg pool acquisition | mitigate | Explicit pool maximum and acquire timeout; fail clearly rather than waiting indefinitely for a connection. |
| T-04-SC | Tampering | Prisma package install | mitigate | Prisma CLI/client/adapter exactly 7.10.1; no Prisma 8 RC and no MikroORM packages. |
</threat_model>
